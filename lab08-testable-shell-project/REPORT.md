# Отчет по лабораторной работе №8

## Ответы на контрольные вопросы

1. **Как тестировать функции, которые изменяют окружение?**
   Функции, которые меняют переменные окружения, создают файлы или меняют текущий каталог (`cd`), тестировать нужно в **изолированном окружении**. Для этого в Bats используется функция `setup()`, которая запускается перед каждым тестом (создает временную папку, копирует туда фикстуры) и `teardown()`, которая очищает за собой. Кроме того, хорошей практикой является вызов таких функций в подпроцессе (`$(...)`), чтобы их изменения не «протекали» в основной процесс теста.

2. **Почему тесты Bash часто становятся хрупкими?**
   Тесты на Bash хрупкие из-за зависимости от внешнего окружения:
   - *Разные версии утилит*: `awk`, `stat`, `find` могут вести себя по-разному в Linux, macOS и Git Bash.
   - *Локали*: сортировка и сравнение строк зависят от `LC_ALL`.
   - *Побочные эффекты*: если тест не убрал за собой временные файлы, следующий запуск может упасть.
   - *Состояние гонки*: фоновые процессы или асинхронный I/O могут завершиться в непредсказуемый момент.
   Поэтому так важно изолировать тесты и явно задавать все переменные окружения (например, `LC_ALL=C`).

3. **Какие зависимости нужно мокать?**
   В Bash мокают (подменяют) внешние команды, которые:
   - Обращаются к сети (например, `curl`, `wget`).
   - Требуют прав `root` (например, `chown`, `mount`).
   - Возвращают нестабильные данные (например, `date` для проверки генерации уникальных ID).
   - Медленные (например, `sleep`, `sha256sum` на больших файлах).
   Мокать нужно через подмену `PATH`: создается временная папка с фейковым скриптом (как мы делали в Лабе №6 для `curl`), и эта папка ставится в начало `PATH` перед запуском теста.

4. **В чем различие между проверкой покрытия строк и проверкой поведения?**
   - **Покрытие строк (Code Coverage)**: проверяет, сколько строк кода было выполнено во время тестов. Если строка не выполнялась, значит, тесты до нее не дошли. Это метрика «количества», но она не гарантирует, что результат работы функции был правильным.
   - **Проверка поведения (Behavior Testing)**: проверяет, что функция или скрипт выдает ожидаемый результат на входных данных (например, «при падении команды функция `retry_cmd` возвращает код ошибки»). Это метрика «качества»: тест проверяет бизнес-логику, а не просто факт запуска кода.
