# Отчет по лабораторной работе №7

## Ответы на контрольные вопросы

1. **Почему резервная копия без проверки восстановления ненадежна?**
   Потому что наличие файла архива не гарантирует его целостность. Архив мог побиться при передаче, диск мог выдать bad-блок, или процесс резервного копирования мог прерваться. Без процедуры `verify` и тестового `restore` вы узнаете об этом только в момент реальной аварии. Принцип: «Непроверенный бэкап — это не бэкап».

2. **Чем хеш манифеста отличается от хеша архива?**
   Хеш архива (мы считаем его в `meta/`) проверяет целостность **самого файла архива** (например, `.tar.gz`). Если файл повредился, `verify` это покажет. Хеш в манифесте (для каждого файла) проверяет целостность **отдельных файлов внутри** архива. Это нужно для точного восстановления, дедупликации и понимания, какие именно файлы изменились.

3. **Почему нельзя доверять именам файлов из внешнего архива?**
   Из-за уязвимости **Path Traversal** (обход каталога). Злоумышленник может создать архив, внутри которого будет файл с именем `../../etc/passwd`. Если разархивировать его от имени `root`, можно перезаписать системные файлы. В нашем скрипте реализована защита: мы сканируем список файлов (`tar -tf`) на наличие `..` и блокируем восстановление.

4. **Как обеспечить идемпотентность операции создания снимка?**
   Идемпотентность означает, что повторный запуск не меняет результат. В нашем решении мы генерируем уникальный ID на основе времени и случайного числа. Если запустить `create` дважды, создадутся два разных снимка с одинаковыми данными (это дублирование). Для истинной идемпотентности нужно перед созданием проверять, не существует ли уже снимок с таким же хешем манифеста, и пропускать создание, если данные не менялись.
