# Отчет по лабораторной работе №5

## Ответы на контрольные вопросы

1. **Почему параллельное выполнение не всегда ускоряет программу?**
   Ускорение ограничено законом Амдала: если часть программы выполняется последовательно (например, чтение файла задач), она становится узким горлышком. Также параллельные процессы конкурируют за CPU, дисковый I/O и память. Если задача упирается в диск, параллелизм не даст прироста.

2. **Как обнаружить и предотвратить потерю фоновых процессов?**
   Потеря происходит, если родительский скрипт завершается раньше дочерних. Чтобы избежать этого, нужно всегда вызывать `wait` для фоновых процессов. В нашем скрипте используется массив `ACTIVE_PIDS` и цикл `wait` для каждого PID. Дополнительно `trap` на `EXIT`/`TERM` гарантирует, что при аварийном завершении все дочерние процессы получат `SIGTERM` и `SIGKILL`.

3. **Чем полезен `wait -n`?**
   `wait -n` ожидает завершения *любого* из запущенных фоновых процессов. Это идеально для пула воркеров: запускаем N задач, а как только одна завершается, `wait -n` возвращает управление, и мы запускаем следующую.

4. **Для чего нужны `flock` или атомарный `mkdir`?**
   Это механизмы блокировки. Если несколько параллельных процессов пишут в один файл, их вывод перемешается. `flock` блокирует файл для одного процесса. Мы избежали этой проблемы, заставив каждую задачу писать в уникальный файл `${task_id}.result`.
